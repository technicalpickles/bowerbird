## What shipped

The full multi-tool live-streaming surface:

- `crates/daemon/src/api/ws.rs` — WebSocket endpoint at `GET /ws`, bearer-auth via header (priority) or `?token=` query (fallback), topic-subscription grammar with parser-level wildcard rejection, per-connection coalesced `DroppedFrame` emission, two-phase graceful shutdown emitting protocol-level `close` before the WS control close.
- `crates/daemon/src/broadcast/` — `BroadcastHub` around `tokio::sync::broadcast` with `MIN_CAPACITY = 2` floor so the Event+State pair fits any subscriber's ring buffer; `Topic` parser and matcher with grammar-strict literal/wildcard distinction.
- `crates/daemon/src/projection/snapshot.rs` — `snapshot_for_topic` reads `session_projections` on demand, dedupes against the pre-existing subscription set, applies `current_state_for_read` per row, and short-circuits without touching SQLite when the new topic is already covered.
- `crates/daemon/src/projection/session.rs` — `write` is now the sole publisher of user-facing `Event` + `State` frames (sentinel writers excluded by design); publish is statically commit-gated by control flow.
- `crates/daemon/src/ingest/writer.rs` — broadcaster threaded into the steady-state and shutdown-drain paths so persisted events fan out to live subscribers.
- HTTP middleware stack from the Epic 1 retro fold-in: `SetRequestIdLayer` → `TraceLayer` (with `RedactedSpan` so `?token=…` never reaches a span) → custom `timeout_middleware` → `RequestBodyLimitLayer` → auth → handler; WS upgrade exempt from post-upgrade timeout/body-limit.
- `crates/protocol/src/ws.rs` — `SyncFrame::new` and `DroppedFrame::new` typed constructors with relational invariants enforced at construction; both structs `#[non_exhaustive]` to block struct-literal construction outside the protocol crate; `ServerMessage::Unknown` `#[serde(other)]` catch-all so future variants decode gracefully under the asymmetric serde policy.
- 8 new entries in `docs/protocol-changelog.md` under v1.0 → v1.1; epic-level back-amends to `epics.md` (Subscribe wire shape clarification) and `prd.md` (Subscribe example) per retro Agreement A2.

## What was hard

### The cursor-corruption bug (Story 2.4 review finding R1)

**What happened:** `dispatch_envelope` returned `bool` for "was this envelope handled without error." Both call sites (steady-state `rx.recv()` and `drain_backlog_under_state`) set `last_delivered_event_id = Some(ev.event_id)` BEFORE calling `dispatch_envelope`, on the assumption that "handled" implied "delivered." But the function's first branch is `subscriptions.iter().any(|t| t.matches(envelope))` — if no subscription matched, the function returned `true` without sending anything. A `state.session.*`-only subscriber would have its recovery cursor advance on every `events.*` Event envelope it never received. The next `Dropped` frame's `first_dropped_event_id` would point past the actual gap.

**Why it landed:** The cursor advance and the dispatch decision were physically separated in the source — cursor mutation in the calling arm, match logic deep in `dispatch_envelope`. Bool return collapsed three real outcomes (delivered, filtered, socket closed) into one signal. The fix introduces `DispatchOutcome { Sent, Filtered, Closed }` and gates cursor advancement on `Sent`-for-`Event` only.

**Why it took a code review to catch:** The Story 2.4 author tested `events.*` subscribers (cursor advance is correct for them) and `state.session.*` subscribers (no cursor advance because the State envelope is what matches). The pathological case is the **mixed** scenario: a `state.session.*`-only subscriber on a daemon with active `events.*` traffic. That cross-subscriber-topology test wasn't in the original AC matrix; the review explicitly added `state_only_subscriber_does_not_advance_cursor_on_unrelated_events` as the regression coverage.

**Generalizable lesson:** **Return values should disambiguate the outcomes the caller actually cares about.** This is the same shape as Epic 1's "HTTP-shaped status codes on a non-HTTP wire" lesson — borrow expressive vocabulary even when the local cost feels like over-engineering. A three-variant enum is structurally cheap and removes a class of caller misuse permanently.

### The coalescing policy entangled with the wire path (Story 2.4 review finding R2)

**What happened:** Initial implementation of `emit_dropped_or_coalesce` was an `async fn` that called `tokio::time::Instant::now()` internally, conditionally awaited a `socket.send(...)`, and threaded mutable state through references. Testing it required real sockets, real `tokio::time::sleep`, and a real broadcast channel; the original tests used 300ms wall-clock sleeps that would flake under CI scheduler pressure.

**The fix:** Pure-policy extraction. `coalesce_decision(now: Instant, last_dropped_at: Option<Instant>, pending: &mut PendingDrop, last_delivered: Option<EventId>, n: u64, window: Duration) -> CoalesceDecision` is synchronous, takes `Instant` by value (constructable from `Instant::now() + Duration` arithmetic in tests), and returns a `CoalesceDecision { Emit { count, first, last }, Suppress }`. The 7 unit tests fabricate fake `Instant` ladders entirely in arithmetic — no runtime, no scheduler, no socket.

**Generalizable lesson:** **When test determinism is hard, look for an `Instant`-by-value seam.** The wire-side `emit_dropped_or_coalesce` still exists as the integration glue, but the policy contract — first-lag emits, within-window suppresses-and-accumulates, expired window emits-pending-plus-new, captured-`first` survives intra-window cursor advance — lives in pure code that 7 tests verify deterministically. Two failed review rounds in a row asked for this; the second one specified the exact seam shape.

### The release-build-disabled `debug_assert!` (Story 2.2 review finding F2)

**What happened:** `projection::session::write` had a `debug_assert!(!matches!(envelope.kind, EventKind::RecordingStarted | EventKind::RecordingEnded), ...)`. In debug builds (tests + local dev), passing a sentinel kind would panic. In release builds, it would silently commit and then publish the sentinel through the user-facing surface — the exact thing AC #7 forbids.

**Generalizable lesson:** **`debug_assert!` is a developer's tool for catching invariant violations during testing, not a runtime invariant enforcer.** When a check protects an external contract (the wire surface, in this case), it must be a runtime check. The fix returns `Err(Error::Projection(...))` before pool checkout, and the regression test (`projection_write_rejects_sentinel_kinds_at_runtime`) exercises the release-build path explicitly.

### The "snapshot failure silently un-subscribes the client" round-trip (Story 2.3 reviews R3 and R7)

**What happened:** First review round flagged "if `snapshot_for_topic` returns `Err`, the Subscribe arm logs and inserts an empty `Vec`, then calls `subscriptions.insert(t)` — the client cannot distinguish a transient DB error from a successful subscribe on an empty daemon, and retrying the same Subscribe deduplicates against the now-inserted topic." First-round fix: don't insert the topic on snapshot failure.

Second review round (same epic, same story) flagged the opposite: "now the WS is open but the topic isn't actually subscribed; V1 has no Subscribe ack/error frame, so the client can't detect the silent-unsubscribe — future live `State` frames for that topic will not be delivered."

Second-round resolution reverted to the original log-and-insert-empty policy and documented the trade-off in the Subscribe-arm header to prevent a future re-flip: snapshot retry must go through reconnect (which gets a fresh `pre_existing` set), not through re-Subscribe on the same connection.

**Generalizable lesson:** **Both directions of a binary trade-off can be wrong if the underlying protocol is missing a primitive.** V1 has no Subscribe ack/error frame. With the protocol fixed, "live broadcast keeps flowing, snapshot may be absent" is strictly better than "silently unsubscribed," because the connection-level retry mechanism (reconnect) still works. The first-round reviewer's framing was correct as a critique of the silent-empty-snapshot behavior, but the proposed fix (don't insert) opened a worse failure mode. The right place to fix this is the protocol itself, deferred to a future story; the in-story fix is the least-bad operating point with the trade-off documented inline.

### Different author, different stack failures (Story 2.5 debug log)

**What happened:** Story 2.5 was authored by GPT-5 Codex (vs. Opus 4.7 for 2.1–2.4). The debug log records several sandbox-specific dependency-resolution failures (`cargo check` failed because `index.crates.io` was unreachable; `cargo check --offline` failed because `tempfile` wasn't in the local registry; `cargo test` failed similarly). **Generalizable lesson:** **The contract-test suite has a serialization requirement that lives in the heads of the authors, not in the repo.** When a different model came in, the discipline reasserted itself only via the debug log. Worth surfacing into a `CONTRIBUTING.md` or `README.md` test note (see action items).

## Key insights

1. **The Epic 1 retro Agreements (A1 standards-by-default, A2 back-amend) graduated from rules to muscle memory in this epic.** Every story applied them without reminding. The protocol-changelog grew 8 entries (a new entry per story plus mid-story review corrections), and the upstream amendments (epics.md AC#2, prd.md Subscribe example) were committed alongside the implementation, not as a follow-up sweep. A3 (narrate the NDJ ingest framing honestly when 4.4 lands) is the only carryover not yet exercised — Story 4.4 hasn't started.

2. **Test infrastructure compounds across stories when helpers are visibility-promoted, not duplicated.** `story_2_1_ws::{spawn_test_daemon, connect_authed, parse_hello, read_text_frame_or_close}` was promoted `pub(super)` for `story_2_2_publish`; `story_2_2_publish::{WsStream, ProbeKind, wait_subscribe_live, wait_subscribe_live_all, connect_until_ready, publish_via_projection, parse_event_frame, parse_state_frame}` was promoted for `story_2_3_snapshot`. Each story adds ~1–2 reusable helpers, and the per-story new-test count (8 contract tests for 2.4, 8 for 2.3, 6 for 2.2) stayed roughly constant despite the surface getting more complex. The cost of writing the N+1-th contract test is bounded.

3. **The asymmetric serde policy needed an enum-variant escape hatch to be future-proof.** `deny_unknown_fields` is a struct-level attribute and silently accepts the gap at the enum-tag level. Without `#[serde(other)] Unknown` on `ServerMessage`, the "additive within v1.x" claim in the changelog was vacuously true (no producer was about to add a variant) but would have broken hard on the first `ServerMessage::Dropped` Story 2.4 added. Worth re-checking all wire enums in `crates/protocol` (envelope, frame, error variants) for the same gap — see action items.

4. **One-code-path-with-an-Instant-seam beats one-code-path-without.** The Story 2.3 review's per-id query suggestion was pushed back on (one code path > branch), and that was the right call. But the Story 2.4 coalescing extraction is the dual: *also* one code path on the wire side, but with the policy decision behind an `Instant`-by-value function boundary so tests don't need a runtime. The pattern: when the function reaches for `Instant::now()` or `tokio::sleep`, factor the policy out and pass `Instant` in.

5. **`#[non_exhaustive]` is the right enforcement primitive for "all construction goes through `new`."** `SyncFrame` (2.3) and `DroppedFrame` (2.4) both used it. `Deserialize` still works (the attribute restricts construction *outside* the defining crate; within-crate serde derive is unaffected). Public field reads stay available so consumers can inspect. The pattern: typed constructor + `#[non_exhaustive]` + `Deserialize` = asymmetric inbound/outbound enforcement at the type system level.

6. **Code review caught real bugs every story, with no false-positive overhead worth re-litigating.** 36 review findings, 33 patched, 3 deferred with reasoning, 0 reverted-back-on-author-pushback (the AC#4 wording change was a story-spec correction, not a reversal). The review investment is paying off — every story shipped with bugs that production-style fuzzing or real users would have found later, when fixing them would be expensive.

## Team agreements (additions to A1/A2/A3 carry-forward)

### A4. Boolean returns disambiguate or grow into typed variants

When a function returns `bool` and the call site uses the boolean to gate a side-effect on a different state (e.g., advancing a cursor based on "handled"), the return type should be a named enum with variants for each outcome the caller cares about. The cost is low (a 3-variant enum is structurally trivial) and the bug class it prevents (cursor corruption from misinterpreting "handled" as "delivered") is silent and discovered far from the bug site.

**Trigger condition:** a code review finds the caller doing different work based on the bool, AND the function could plausibly return `true` for either reason.

### A5. `debug_assert!` is for invariant *catching*, not invariant *enforcement*

When a check protects an external contract (the wire surface, a public function signature, a documented API guarantee), use a runtime `Err(...)` return or `unreachable!()` path, not `debug_assert!`. `debug_assert!` is appropriate for caller-controlled internal invariants where the test pass is what proves the invariant holds — not for protections that must survive release builds.

**Trigger condition:** the assertion guards against `pub fn` or `pub struct` misuse that would violate a contract documented outside the source file (in a story, AC, or changelog).

### A6. When test determinism is hard, look for an `Instant`-by-value seam

When a function being tested calls `tokio::time::Instant::now()` or `tokio::time::sleep()` internally, the test must either pause the runtime (`tokio::test(start_paused = true)` + `tokio::time::advance`) or work around it with wall-clock sleeps. The wall-clock approach is flaky under CI scheduler pressure. The pause approach is fragile when the system under test interleaves with sockets, broadcast channels, or other runtime-coupled state.

The third option, and usually the right one for policy-shaped functions: factor the decision out into a pure synchronous function that takes `Instant` (and any other clocked value) by value. The wire-side glue still exists, but the policy contract becomes deterministically unit-testable via arithmetic on fabricated `Instant` ladders.

**Trigger condition:** a code review asks for "deterministic coverage" of a function that currently sleeps or polls real time.
