## What was hard

### The write budget that was not a bound

**What happened:** the shim's `SO_SNDTIMEO`/`SO_RCVTIMEO` bound each kernel *wait*, not the operation. macOS `sosend` re-waits per buffer refill inside one `write(2)`, so 1 MiB against a peer draining 8 KiB/ms took 189ms and returned `Ok` from a single syscall. Worse, 5.16's inline fix (`write_all_within`) shipped guarded by a green test whose re-arm path never executed: its mock peer drained slower than the budget, so 10/10 runs took the untested branch. The false "write + read ≤ 5ms" claim lived in six doc sites plus a green test across 8/8 CI checks.

**The fix:** back out the fix, state the honest shape everywhere, and file the behavior as its own story (5.17) with the measurement table attached. 5.17 shipped `write_bounded` (8 KiB chunks + wall-clock deadline, so the kernel's re-wait loop has nothing to loop over), bounded the read symmetrically, and its AC #6 requires any bound-verifying test to be observed failing against the restored-unbounded code.

**Generalizable lesson:** **a test whose mechanism is unreachable is not a weak test, it is a false one** (5.16 Completion Note 9, verbatim). It is worse than no fix: it manufactures confidence.

### Seven review passes on the launchd lifecycle

**What happened:** Story 5.9 accumulated ~30 findings over 7 passes, dominated by launchctl-state ambiguity (unverifiable `launchctl print` vs "not loaded", re-litigated across five passes) and lifecycle-ownership questions. Two findings were genuinely material (stop must bootout through the lifecycle owner; singleton liveness is the flock, not pid-file content). Pass 6 deleted pass 5's fix.

**The fix:** a mid-story correct-course ratified `BOWERBIRD_DATA_DIR`/`BOWERBIRD_INGEST_SOCK` as test seams rather than a relocatable-install feature, dismissing ~9 findings at the root (AC 12, ADR 0007 scope note). The maintainer closed at pass 7, naming the accreted defensive complexity as the real remaining risk and routing it to dogfood-on-real-hardware then a consolidation pass (bean `gt-gcqa`).

**Generalizable lesson:** **when findings are reviewer-theoretical rather than from running the thing, additional passes add risk instead of removing it.** The stop condition for review is not "no findings left"; it is "the remaining findings are cheaper to meet in the field."

### Benches misled on machine state, then on runner noise

**What happened:** the `hot_path` bench misled three separate times on machine state (leftover CPU spinners from a reviewer experiment: +113.65%; running straight after `scripts/test.sh`: +61.87%; a polluted 70.86ms p99 during 5.17). Then two CI gate reds fired on diffs that could not have caused them, and 5.18's scoping found the filed diagnosis only covered one of two defects: daemon p99 was literally the sample max at n≤50, while the shim's 15ms absolute budget was simply stale against a shifted distribution.

**The fix:** `scripts/run-bench-gate.py` best-of-2 (bounded at two attempts, recorded in the step summary, structurally unable to mask a deterministic regression), daemon shapes to n=200, baselines reseeded from five no-change CI runs, and the regression ratio moved to 2.0 from measured cross-window spread after the review's pre-agreed trigger fired hours later, on the review-fixes push itself.

**Generalizable lesson:** **two red benches that were both noise teaches reflex-rerunning, which is exactly how a real regression eventually gets waved through** (5.18, verbatim). Sanctioned retries must be bounded, recorded, and incapable of hiding a deterministic failure; everything beyond that is an investigation.

### The record was wrong more often than the code

**What happened:** the dominant finding class across the whole epic was record-vs-reality drift, not code defects: comments asserting things the same diff disproves (5.16 had three copies of one false claim; the resolution fixed two and re-added the third), ACs describing behavior the code had moved past (5.10, four passes), Completion Notes over-claiming what was verified (5.14, 5.16, 5.17), File List vs `git status` drift biting four stories, and `deferred-work.md` wrong on three of seven entries the same commit added (5.16).

**The fix:** reviews treat prose as load-bearing and patch it like code; the three-layer reviews from 5.13 onward carried explicit record-hygiene passes.

**Generalizable lesson:** in a repo where prose steers future agents, **stale records are not cosmetic; they are the defect class that costs the most review budget.** Budget for it, and keep the File-List automation question alive (see AI-3).

### External infrastructure stalled the epic for seven weeks

**What happened:** a GitHub Actions billing failure blocked Story 5.5 on 2026-05-29; combined with the dogfood window closing out, the epic went quiet from 2026-06-11 to 2026-07-28. The outage also hid a Linux clippy break from 5.9 (CI could never run to catch it) and meant `daemon-bench-gate` had literally never executed before 5.5 resumed.

**The fix:** on resume, fix-forward (clippy repairs, baseline seeding) and a deliberate, documented punt of the Linux burst baseline (`burst_p99_nanos: 0`) rather than pretending coverage existed.

**Generalizable lesson:** **a gate that has never run is aspirational, no matter what the workflow file says.** And the flip side: the written record (sprint-status chain, story files, parked handoffs) made a seven-week cold resume cheap. The pause cost calendar time, not context.

## Key insights

1. **Dogfooding is the substrate's review of record.** Every correctness story in the epic traces to a dogfood finding, and 5.12's insistence on a real fresh-machine install (rather than declaring the pipeline done at green CI) is what surfaced the shim stall. For a project whose product is observing real sessions, usage finds what review structurally cannot.

2. **A green test is not evidence; a test observed failing against the broken code is.** 5.16's false test is the canonical case, 5.17 AC #6 is the rule written down, 5.18's branch-matrix requirement cites it as precedent, and 5.13's link checker catching a file outside its own AC list is the same principle inverted. This is now team agreement A13.

3. **Recurring findings across passes signal an undecided design question.** 5.10 named it after three passes on one sanitizer; 5.7's backfill drew findings on four passes because the scenario itself was unreal; 5.16's second attempt was refused in favor of a story. The productive responses were: ground the premise (measure, spelunk), decide the design, delete the surface, or file with evidence. Never a fourth patch. Now A16.

4. **Verification infrastructure must be trustworthy before it can accept work.** 5.18 jumping the queue ahead of 5.17 ("landing perf work through a gate with that failure amplitude proves nothing") is the epic's clearest sequencing decision, and its Decision trigger firing the same day validated both the finding and the mechanism.

5. **Numeric story ids rotted four times.** Old 5.5→5.6→5.7, old 5.7→5.11 through 5.10→5.14, then 5.11→5.12 through 5.14→5.15: every insertion forced a renumber sweep across epics.md, sprint-status, proposals, and story cross-references, and at least one stale-number bug reached a story file. The maintainer's standing slugs-over-ordinals rule exists for exactly this; whether BMAD story keys can be slug-first is a tooling question worth raising before the next epic-scale plan.

6. **The epic more than doubled by design, not by scope creep.** 7 planned → 18 shipped, but every insertion traces to a dogfood finding, a review escalation with evidence, or a named proposal. The sprint-change-proposal machinery kept an 11-insertion epic auditable, which is why this retrospective could be assembled from the record alone.

## Significant discoveries

### Discovery #1: The shim's write budget never bounded anything

**What:** since Story 1.5, the `SO_*TIMEO` socket options bounded each kernel wait, not the operation; a slow-draining peer could hold a single `write(2)` open for 189ms while the shim reported success. Both platforms affected (Linux measured ~31x more permissive than macOS on the write arm). Pre-existing, found only because 5.12 required a real fresh-machine dogfood.

**Impact on post-V1:** fixed by 5.17 (chunked writes + deadlines); multi-chunk payloads over 8 KiB are now explicitly best-effort, an accepted Axiom 3 trade with the numbers recorded at `crates/shim/src/socket.rs::WRITE_BUDGET_MS`. The loss trigger includes a descheduled shim, not only a starved daemon.

**Generalizable lesson:** OS API semantics stated in comments are hypotheses until measured at the trust boundary. The 5.16 rule (measure before changing code) is what caught this; keep it.

### Discovery #2: The daemon's single thread is starvable, and Linux runners prove it

**What:** 5.16's measurement isolated the dropped-event cause as OS scheduler starvation of the `current_thread` runtime under compile-storm load (p50/p90 unmoved from idle, p99 detonating). Separately, ubuntu-latest shows an intermittent per-event ~40ms stall (`0f95d384`) that resurfaced on a chaos-free tree and keeps the Linux burst bench lane unarmed.

**Impact on post-V1:** insulating daemon ingest from scheduler starvation (`719e7027`) is on record as "the real exposure"; until then the shim-side bounds cap the blast radius at dropped events, never a blocked Claude.

**Generalizable lesson:** a pinned distribution body with a detonating tail means starvation, not slow code; diagnose scheduling before touching the code path.

### Discovery #3: The namespace check was testing the wrong crates

**What:** the earlier crates.io pre-check recorded in sprint-status had queried names that are not workspace packages (`bowerbird-cli`, `bowerbird-client`) and never checked `bowerbird-shim` or `protocol`. The 5.15 re-run against the real five-package set found `protocol` taken by an unrelated 2016 crate with ~160k downloads.

**Impact on post-V1:** publishing deferred with no placeholder (ADR 0011); rename plan (`bowerbird-protocol`, `bowerbird-adapter-claude`) verified free and recorded; the vendored libsqlite3-sys patch not traveling to crates.io consumers is the second blocker (the close deadlock would return). Revisit triggers are observable and in the ADR.

**Generalizable lesson:** verification must enumerate the real artifact list from the workspace manifest, not a remembered one. A pre-check that tests the wrong names is worse than none; it manufactures the same false confidence as an unreachable test.

### Discovery #4: bowerbird has no non-schema data-migration facility

**What:** 5.6 built a startup repair for stale projections, then deleted it in favor of "fix `bower.db` by hand or truncate it"; 5.7's backfill deletion leaned on the same "pre-release means nuke the db" stance. Both were correct calls today and both cited the same gap: there is no mechanism for projection backfill/reprojection with history-completeness safety.

**Impact on post-V1:** fine while no released database must survive an upgrade. The moment a release promises data survival, the deferred migration-era backfill work (deferred-work.md, 5.7 entries) stops being optional.

**Generalizable lesson (or concern):** the nuke-the-db stance has an expiry date and its trigger is observable: the first tag whose upgrade notes cannot say "delete your database". Watch for it at the next protocol or schema change.

## Team agreements (additions to the A1..A12 carry-forward)

### A13. Bound-verifying tests must be observed failing against the broken code

**Why:** two green tests guarded the shim write stall while it was live; 5.16's guard test passed 10/10 without ever executing the mechanism it claimed to verify.

**Trigger condition:** any test whose purpose is to verify a bound, guard, branch matrix, or failure path.

**How to apply:** restore or simulate the broken behavior, watch the test go red, then keep it. 5.17 AC #6 and 5.18 AC #4 are the templates.

### A14. Gate reds get diagnosed, never reflex-rerun

**Why:** 5.18's own words: noise reds teach reflex-rerunning, which is how a real regression eventually gets waved through.

**Trigger condition:** a CI gate fails on a diff that plausibly could not have caused it.

**How to apply:** the best-of-2 wrapper is the only sanctioned retry (bounded at two, recorded in the step summary, cannot mask a deterministic regression). Anything beyond it is an investigation, filed with run links before any rerun.

### A15. Release-mechanics stories may skip adversarial review by maintainer decision

**Why:** ratified across 5.5, 5.12, and 5.15. The pipeline run is the adversarial review: six jobs, two platforms, a real cross-version upgrade, and it found five latent bugs that code reading had not.

**Trigger condition:** a story whose diff is release process and evidence, not product behavior.

**How to apply:** the skip is an explicit maintainer decision recorded in the story; the record shape (Completion Notes, Change Log, File List) stays mandatory.

### A16. Recurring findings escalate to a decision, not a fourth patch

**Why:** 5.7 (four passes on a backfill → deleted), 5.10 (three passes on a sanitizer → surface deleted after grounding the premise), 5.9 (scope ratified mid-story, ~9 findings dismissed at the root), 5.16 (second fix attempt refused; story filed with evidence).

**Trigger condition:** the same surface draws findings on three consecutive passes, or a fix escalates rather than converges.

**How to apply:** stop patching. Ground the premise (measure, spelunk, reproduce), then either decide the design (correct-course), delete the surface, or file an evidence-attached story.
