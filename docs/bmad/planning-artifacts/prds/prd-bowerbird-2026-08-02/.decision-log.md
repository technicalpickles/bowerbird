### Original PRD decisions

- **Substrate, not actor.** bowerbird collects and routes agent events; it never interprets,
  derives, or prioritizes. Rationale: the thinnest layer is the most valuable one; interpretation
  belongs to tools, keeping the substrate small, stable, and trustworthy.
- **Target user is the tool builder, not the end user.** V1 serves developers who build tools on
  agent activity; their users (Journey 3's Priya) follow once tools exist.
- **Experience MVP scoped to one user (pickles).** Success gate: the maintainer iterates on
  multiple simultaneous tools against live Claude Code sessions with zero instrumentation friction.
  Rationale: the riskiest assumption is "are experiments actually cheap," only usage validates it.
- **Claude Code is the only V1 adapter.** It is the reference implementation; a second adapter
  (Codex, Gemini, or Cursor) is post-MVP, ideally landed by an external contributor to validate
  the adapter model.
- **Two socket surfaces.** Unix domain socket (0600, no auth) for shim ingest; loopback TCP with
  bearer token for tools. Rationale: kills the "how does the shim get the token" problem and
  removes auth overhead from the 5ms hot path.
- **Additive-only protocol stability within v1.x (hard guarantee).** No fields removed, no types
  changed; tools built on v1 run on any v1.x daemon. Behavioral compat is best-effort with two
  carve-outs (security fixes, spec-incorrect bug fixes). CI-enforced `protocol-changelog.md`
  entry required for any protocol-crate change. v2, if ever, ships as a parallel `protocol@v2`
  tree with a documented transition window.
- **Performance contracts as success criteria.** Shim < 5ms p95, hook-to-projection < 50ms,
  end-to-end < 100ms, daemon < 0.5% idle CPU / < 50MB RSS, core 5K-7K LOC. If a bar can't be met,
  the answer is an ADR documenting the real number, not a silent miss.
- **Language matrix: Rust core, TypeScript examples.** Protocol/shim/daemon/adapter in Rust
  (shim with no async runtime); reference example tools in TypeScript/Node under `docs/cookbook/`.
- **Distribution: prebuilt GitHub Releases binaries primary, source build secondary.** macOS
  arm64/x86_64 + Linux x86_64 glibc. Homebrew tap explicitly deferred: solo audience doesn't
  justify tap maintenance.
- **Event log unbounded in V1 (NFR4).** Escape hatch is deleting `bower.db` by hand; managed
  `bowerbird gc` is post-V1 and the truncation policy decision is deferred.
- **`/metrics` reserved, not implemented (NFR18).** `/healthz`, `/readyz`, `/status` are enough
  for V1; Prometheus waits for usage evidence.
- **No rate limiting or burst protection (NFR7).** Single-developer workloads only; documented
  design limitation, not an oversight.
- **Quickstart works without a live agent.** `bowerbird replay` + bundled fixtures let the
  quickstart and all three cookbook examples run with no Claude Code session. Docs path
  (quickstart, presenter-authoring, protocol, cookbook) is a launch deliverable, not post-launch.
- **Solo-maintainer contribution model.** Auto-close by default, weekly triage; V1 does not need
  community adoption to succeed, it needs one user to find it genuinely useful.

### Post-PRD amendments

- **`docs/no-list.md` (V1 scope cuts, hardened post-PRD):** no Windows (can't test locally),
  no distro packaging at all (amends the PRD's Journey 3 `brew install` framing: V1 surface is
  tarball + `cargo install --git`), no HITL backflow, no tool blocking (side-channel, never a
  control plane), no personas/agent-roles (identity is `(source, session_id)`), no LAN/multi-host
  (loopback only; multi-host needs real auth), no musl prebuilts, no macOS code signing or
  notarization ($99/year not justified yet), no structured JSON logging, no crates.io publishing.
- **ADR 0011 (2026-08-02): crates.io publishing deferred at v0.1.0, no placeholder reservation.**
  Supersedes the PRD/no-list "namespace may be squatted" framing: the names were verified free
  (except `protocol`, taken by an unrelated crate; rename plan `bowerbird-protocol` recorded).
  Real blockers instead: the vendored libsqlite3-sys WAL-deadlock patch doesn't travel to
  crates.io consumers, path deps lack version keys, and Rust-API semver commitment is premature
  (the stable surface is the wire protocol, not the Rust API). Distribution stays GitHub Releases
  + `cargo install --git --tag`; this also amends the PRD's plain `cargo install bowerbird`
  wording (Installation Methods, Journey 3, FR28).
- **ADR 0008 (2026-06-02): server-side session filtering.** Additive wire change from the
  dogfood-triage loop: `GET /sessions` gains `?state=`/`?since=`/`?limit=`, and WS
  `Subscribe` gains an optional `states` filter scoping the snapshot-on-subscribe burst.
  Empty/absent = unfiltered on both surfaces, preserving v1.0 behavior; the presenter supplies
  the predicate so the daemon never decides relevance on its own (substrate axiom held over the
  cheaper fixed-default alternative). Filters only; no eviction of `Ended` rows.
